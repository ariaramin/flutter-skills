# Senior Flutter Architecture Skill

A Flutter/Dart specialization of the source `senior-mobile-architecture` skill.

## What this adds

The base skill already provides senior mobile reasoning around requirements, architecture tradeoffs, repositories, offline sync, pagination, retries, state ownership, modularity, testing, and performance.

This specialization translates that reasoning into Flutter-specific operating rules for:

- Flutter UI/View/ViewModel boundaries
- state-management package selection without package dogma
- `Future`, `Stream`, isolates, and lifecycle ownership
- navigation, routing, deep links, and route state
- repositories/services and offline-first Flutter design
- dependency injection and composition roots
- widget/unit/integration/golden testing
- Flutter rendering and DevTools-based performance work
- platform channels, Pigeon, plugins, packages, and FFI boundaries
- Dart API and null-safety/code-quality rules
- architecture review and refactoring

## Evidence tags

- `B-D1`, `B-D2`, `B-C`, `B-I` — inherited from the base skill's source-grounded mobile architecture research
- `F` — official Flutter documentation
- `D` — official Dart documentation
- `P` — conventions discovered in the current project

The skill intentionally avoids claiming that one community state-management package or folder template is “the Flutter architecture.”
